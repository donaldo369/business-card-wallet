# UI 레이아웃 재구성 설계

작성일: 2026-09-04

## 배경

현재 UI는 데스크탑과 모바일이 같은 레이아웃을 공유한다. `.app-container`가
`max-width: 860px`로 고정되어 있어 1440px 모니터에서도 화면의 약 40%가 비고,
명함 카드는 2열까지만 표시된다. 그룹 필터·선택 모드·그룹 관리가 하나의 칩 줄에
섞여 있고, 상세 보기는 520px 모달이라 명함을 연속으로 훑기 어렵다.

모바일은 검색·추가·그룹 칩이 모두 화면 최상단에 있어 엄지 도달 범위 밖이고,
그룹 칩이 줄바꿈되어 세로 공간을 크게 먹는다.

이 문서는 데스크탑을 3분할 셸로 재구성하고 모바일을 손 닿는 구조로 바꾸는
작업의 설계를 기록한다. 선행 수리(썸네일 왜곡, 인라인 렌더되던 중복확인
다이얼로그, 미정의 CSS 클래스, 프로덕션 디버그 배너, `alert`/`confirm` 43회,
지연 로딩·sticky 부재)는 이 작업 이전에 완료되었다.

## 목표

- 데스크탑에서 모달을 여닫지 않고 명함을 연속으로 훑을 수 있게 한다.
- 넓은 화면의 가로 공간을 그룹 내비게이션과 상세 패널에 쓴다.
- 모바일에서 주 액션(명함 추가)을 엄지 도달 범위에 두고, 그룹 필터가 세로
  공간을 잠식하지 않게 한다.
- 위를 가능하게 하는 최소한의 컴포넌트 분리를 한다.

## 비목표

다음은 이번 범위에 넣지 않는다.

- 드래그 앤 드롭 업로드, 클립보드 이미지 붙여넣기
- 정렬·필터 옵션 추가 (예: HubSpot 미등록만 보기)
- 표(테이블) 뷰 — 3분할 목록 pane의 폭에 맞지 않는다
- `viewport`의 `user-scalable: no` 해제
- `--text-muted`(#475569) 명도 대비 개선
- 테스트 러너 도입

## 반응형 전환점

| 폭 | 셸 | 상세 표시 |
| --- | --- | --- |
| `< 768px` | 단일 컬럼 + FAB | 바텀시트 |
| `768–1023px` | 단일 컬럼 | 중앙 모달 |
| `1024–1279px` | 사이드바 + 목록 | 중앙 모달 |
| `≥ 1280px` | 사이드바 + 목록 + 상세 | 우측 패널 |

`viewingCard` 상태는 그대로 두고 렌더 위치만 브레이크포인트에 따라 바뀐다.
상세 본문은 `CardDetail` 하나로 두고, 패널·모달·시트가 그것을 감싼다.

## 컴포넌트 분리

`src/app/page.js`는 현재 2868줄이다. 3분할 셸은 이 구조로는 만들 수 없다.

원칙: **상태와 데이터 로직은 전부 `page.js`에 남기고, 표현부만 props로 내려
받는 컴포넌트로 추출한다.** 상태 관리 라이브러리는 도입하지 않는다.

| 파일 | 책임 | 의존 |
| --- | --- | --- |
| `AppShell.js` | 1/2/3분할 CSS Grid 프레임 | 없음 (슬롯만 받음) |
| `GroupSidebar.js` | 전체·그룹·그룹없음 내비, 그룹관리·설정·계정 | 그룹 목록, 개수, 활성 그룹 |
| `CardList.js` | 검색바, 날짜 그룹핑, 선택 모드 | 필터된 명함, 그룹 맵 |

각 컴포넌트는 "무엇을 하는가 / 어떻게 쓰는가 / 무엇에 의존하는가"에 답할 수
있어야 하고, 내부를 읽지 않고도 용도를 알 수 있어야 한다.

## 데스크탑 3분할

### 사이드바 (240px 고정, 자체 스크롤)

- 로고
- 그룹 내비: `전체(개수)`, 각 그룹(색 점 + 이름 + 개수), `그룹 없음(개수)`
- `새 그룹`, `그룹 관리`
- 하단: 사용자 이메일, 설정, 로그아웃

현재 칩 줄에 섞여 있던 그룹 필터·관리가 여기로 이동한다. 칩 줄에는 선택 모드
토글만 남는다.

### 목록 pane (가변, 자체 스크롤)

- 상단 sticky: 검색 + `새 명함 추가` + `텍스트 입력` + 밀도 토글
- 날짜 헤더 sticky (선행 수리에서 이미 적용됨)
- 선택 모드일 때 상단에 선택 액션바
- 밀도 토글: `comfortable`(현행 카드) / `compact`(썸네일 + 이름 + 회사 한 줄).
  CSS 클래스 하나로 전환하며 선택값은 `localStorage`에 저장한다.

### 상세 pane (380px, `≥1280px`, 자체 스크롤)

- 미선택 시 "명함을 선택하세요" 빈 상태
- 선택 시 `CardDetail` 렌더

## 스크롤 구조 변경

현재는 `body`가 스크롤한다. 3분할은 각 pane이 독립 스크롤해야 하므로
`≥1024px`에서만 다음을 적용한다.

```css
@media (min-width: 1024px) {
  html, body { height: 100%; overflow: hidden; }
  .app-shell { height: 100dvh; }
}
```

모바일은 주소창 show/hide 동작 때문에 기존 body 스크롤을 유지한다. 이 분기를
지키지 않으면 iOS Safari에서 스크롤이 잠기므로 주의한다.

## 모바일

각 항목이 적용되는 폭은 다음과 같다. FAB와 그룹 칩 가로 스크롤은 단일 컬럼인
구간 전체(`<1024px`)에 적용하고, 바텀시트는 `<768px`에만, 검색 UX 개선은 폭과
무관하게 항상 적용한다.

1. **FAB** (`<1024px`) — 우하단 고정 카메라 버튼. `bottom: calc(env(safe-area-inset-bottom) + 16px)`.
   선택 모드일 때는 선택 액션바와 겹치므로 숨긴다.
   `텍스트 입력`은 검색바 옆 아이콘 버튼으로 이동한다.
2. **그룹 칩 가로 스크롤** (`<1024px`) — `flex-wrap: nowrap; overflow-x: auto;`,
   스크롤바 숨김, 좌우 페이드 마스크.
3. **바텀시트** (`<768px`) — `Sheet.js`가 `<768px`에서 하단 정렬 + 상단 모서리 라운드 +
   드래그 핸들 + 아래로 스와이프 닫기. safe-area 대응.
4. **검색 UX** (전 구간) — 검색어가 있을 때 지우기(X) 버튼 표시. 검색 결과 0건일 때
   `"○○" 검색 결과가 없습니다` + `검색 초기화` 버튼을 보여준다. 현행은 검색
   결과가 없어도 "저장된 명함이 없습니다 / 새 명함 추가 버튼을 눌러…"라는
   틀린 안내를 한다.

## 함께 처리하는 접근성 보정

해당 컴포넌트를 다시 작성하므로 다음을 함께 넣는다.

- 명함 카드를 키보드로 포커스·활성화할 수 있게 한다 (`button` 시맨틱).
- 모달·시트에 `role="dialog"`, `aria-modal="true"`, 제목 연결.
- `label`과 `input`을 `htmlFor`/`id`로 연결한다.

## 데이터 흐름

상태는 `page.js`에 그대로 있고 단방향으로 내려간다.

```
page.js (상태 + Supabase/HubSpot 호출)
  └─ AppShell
       ├─ GroupSidebar     groups, cardGroupMap, activeGroupId, onSelectGroup...
       ├─ CardList         filteredCards, groupedByDate, selectionMode...
       │    └─ CardListItem card, isSelected, onSelect
       └─ CardDetail       viewingCard, onEdit, onDelete, onSyncHubSpot
```

모달류는 `page.js`가 조건부로 렌더하며 `Sheet`로 감싼다.

## 오류 처리

선행 수리에서 도입한 `useToast()`를 그대로 쓴다. 새 컴포넌트는 자체적으로
오류를 표시하지 않고, 실패는 `page.js`의 핸들러가 받아 토스트로 알린다.
파괴적 동작(삭제)은 `await confirm({ danger: true })`를 거친다.

## 실행 순서

레이아웃 변경과 대규모 파일 분리를 동시에 하면 회귀 원인을 못 가린다.
2단계로 나눈다.

1. **동작 보존 추출** — 컴포넌트 분리만 하고 화면은 픽셀 단위로 동일하게
   유지한다. 빌드·린트·수동 확인으로 회귀 없음을 확인한다.
2. **레이아웃 적용** — 3분할 셸, 모바일 4개 항목, 접근성 보정을 얹는다.
